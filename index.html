How it works

Six steps from
camera to verdict.

The entire pipeline runs client-side — from browser permission request to final liveness decision, with no round trips to a server.

01

Camera permission

The browser's native permission dialog requests camera access. SpoofNet asks only for what it needs — no microphone, no storage access. Permission is requested once per session and never stored.

Browser API
02

Live feed capture

A short sequence of frames is captured from the webcam stream. The capture window is kept brief — typically under a second — to minimise friction. Frames are processed in memory only.

MediaStream
03

Face detection & alignment

A lightweight pass detects and crops the face region, normalising it to a fixed input size. If no face is found, the user is prompted to reposition — no server call is made at this stage.

On-device
04

Liveness model inference

The <5 MB liveness model runs entirely in-browser via WebAssembly or WebGL. It analyses depth cues, texture patterns, and micro-motion signals that photos and replay videos cannot replicate.

WASM / WebGL
05

Confidence scoring

The model outputs a liveness confidence score between 0 and 1. Your integration sets the threshold — for example, treat anything below 0.9 as a potential spoof and prompt a retry or block.

Configurable
06

Verdict in <20ms

A real/spoof verdict and confidence value are returned to your application. Your app decides what happens next — proceed, challenge, or block. The entire flow takes under 20ms after frame capture.

<20ms
